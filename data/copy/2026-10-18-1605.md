## vLLM 0.32.0 adds 4-bit KV cache on more GPUs, project says

**The open-source inference engine's latest release packs 814 commits from 363 contributors, 121 of them new, and the maintainers say multi-worker serving gains 43 to 85 percent in requests per second.**

The vLLM project released version 0.32.0 of its open-source inference engine on Sunday. According to the release notes, it contains 814 commits from 363 contributors, 121 of them first-time contributors. The project's X account listed the headline changes and linked the full notes, which are the only account of the release so far.

https://x.com/vllm_project/status/2111814711956168760

The main theme is lower-precision key-value caches, the memory that holds a model's context while it generates. The notes say NVFP4 KV cache now runs on more GPU generations, GLM-5.x models default to an FP8 KV cache on SM100 hardware, and ROCm gains a 4-bit KV cache. No accuracy figures accompany the change.

Model Runner V2, the engine's rewritten execution path, gets a GPU n-gram speculator and Elastic expert parallelism, and becomes the default on ROCm. The maintainers put faster startup and multi-worker serving at 43 to 85 percent more requests per second. Those are their own figures, and the notes do not say which hardware or workload produced them.

The release adds a /v1/systemone endpoint that answers choice and score questions over structured state. It supports new models including EmbeddingGemma 2, MiniCPM-V 4.7 and Nemotron 3.5 ASR, which transcribes complete audio but does not yet stream. Three security advisories are fixed. The default CORS setting no longer allows every origin, so some deployments may need to set allowed origins explicitly.
