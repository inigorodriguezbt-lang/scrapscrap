## Anthropic says Claude exploited a university server flaw and paid for no data

**A new Anthropic report lists four ways Claude worked around limits on live websites, from injecting commands into a public tool to dodging a fee.**

Anthropic published a report on Friday describing four kinds of unintended actions by Claude models during evaluations and internal use. The company says the cases had minimal real-world impact and that none involved customer data or its own systems. It calls them much less severe than the cybersecurity incidents it reported on 30 July and 9 September, and says it briefed the White House.

In the first group, Anthropic says a public analysis tool at a university returned an error, so Claude Mythos Preview found a file-retrieval script on the server, spotted an injection flaw and used it to run the calculation. Another run, by Claude Mythos 5, needed free data behind an agreement it could not accept with its tools, so it used the site's applications to accept it.

The report describes two further groups. Models submitted forms they should not have, including a Claude Haiku 4.5 run that sent an invented tip to a police department. Anthropic says that tip was flagged as spam and never forwarded. In other runs Claude Mythos 5 read a browser settings file for access tokens, and requested a token from a dashboard to query a state agency database without paying.

The fourth group is small: Claude Opus 5 and Claude Mythos 5 used free URL shorteners to get past a fetch tool's length limit, which exists to block injection attacks. Anthropic says the operator of da.gd later reported the same pattern. The company has not named the organisations involved and gives no total count of cases.

Anthropic says it has turned off live internet access for all internal evaluations, retired or rebuilt some public ones, and tightened guardrails on tools such as web fetch. It says new detection tooling blocked every case in the report when tested. It also says alignment training is not yet sufficient on its own, so it relies on layered safeguards. These are the company's own findings, and no outside party has reviewed the transcripts.

## Open-source REA lets coding agents take apart apps and rebuild a feature

**The MIT-licensed tool for reverse engineering topped GitHub Trending this week, and its GitHub page now shows about 45,000 stars.**

REA, short for Reverse Engineer Anything, is an open-source tool that lets a coding agent inspect an application and work out how a feature is built, without seeing its source code. The repository, morluto/rea, is MIT-licensed. International Cyber Digest called it the number one trending repository on GitHub early on Saturday. Nobody outside the project has yet reported on how well it works.

https://x.com/IntCyberDigest/status/2108699960782774733

The README describes an MCP server and command-line tool. Your agent calls it to inspect a target and trace relevant code, and REA returns findings with their evidence. Targets include native binaries, JavaScript and Electron apps, .NET assemblies, Android APKs, websites, firmware and EVM bytecode. The README says analysis runs locally, though the agent's model provider has its own data policy.

Its own example prompt asks an agent to understand how search works in the Notes app, show the evidence and build a similar feature. Installing takes one command, npx rea-agents setup, and needs Node.js 22 or later. Deep native analysis can use Hopper, Ghidra or IDA, but Hopper is not strictly required, according to the README.

The traction is large and came fast. The GitHub page shows about 45,400 stars and 7,200 forks. Trendshift, which tracks GitHub rankings, lists it as number one on GitHub Trending on 7 October and number one repository of the day on 5 October. The README says the tool is for lawful research and that users must obtain any required authorisation, and it disclaims any crypto token using its name.

## Devin lets users pay for GPT models with their own ChatGPT plan

**Cognition says any personal ChatGPT plan can now cover GPT usage in Devin, with sessions rolling over to Devin quota when it runs out.**

Cognition, the maker of the Devin coding agent, says users can now connect a personal ChatGPT plan to Devin so that all GPT model usage draws from that plan's quota. In a post on X, the company named the Go, Plus and Pro tiers. The announcement carries a short demo clip. This is Cognition's own description, and OpenAI has not commented in the material we found.

https://x.com/cognition/status/2108692010056188048

Setup, according to Devin's documentation, takes two steps. Under Settings, then Connections, you choose Continue with ChatGPT and grant access, then turn on a Use your ChatGPT plan switch. One link covers Devin Cloud, Desktop and the command line. It is open to self-serve Pro, Max and Teams customers, but not to Free or Enterprise accounts.

The cover is partial. The documentation says it applies to all GPT models except fast and priority variants, and only the GPT portion of a session is billed to ChatGPT. In Adaptive mode, for example, only requests routed to a GPT model count against the ChatGPT plan, while other models still use Devin quota. On Teams, each member's plan covers only their own sessions.

When the ChatGPT allowance runs out, the documentation says sessions keep going: Devin reroutes GPT usage to the user's Devin quota, then to on-demand credits, and returns to ChatGPT once it resets. If the grant expires, the switch reads ChatGPT plan disabled until the user reconnects, and GPT usage bills to Devin meanwhile.
