## Janas runs 80-billion-parameter models on a laptop by streaming experts from SSD

**A new open-source C project says Qwen3-Next-80B writes 24 tokens a second on an integrated-graphics laptop with 32 GB of RAM, against 2.8 for llama.cpp, by reading experts off the SSD.**

Janas, a GPL-licensed project written in C, runs large mixture-of-experts language models by keeping weights on an NVMe drive and reading only the experts each token needs, its README says. It reached the Hacker News front page with 62 points and 25 comments, and the repository showed 100 stars when we read it. The author, Maurizio Cammalleri, calls it "an experiment, not a product".

The README's headline figures come from one machine: an Intel Core Ultra 9 185H laptop with integrated Arc graphics, 32 GB of DDR5 and a 1 TB SSD reading at about 5.7 GB/s. On Qwen3-Next-80B-A3B the author reports 24 tokens a second writing and 62 reading, against 2.8 and 16 for llama.cpp on the same integrated GPU. For Qwen3-Coder-Next it lists 22 against 2.2.

Smaller gaps appear elsewhere. On Qwen3-30B-A3B the README gives 135 reading against 122 and 32 writing against 15, and it says Janas beat llama.cpp on all 13 models compared at Q4_K_M. The one exception it names is unsloth's 3-bit Qwen3-30B build, where reading was 100 against 112. The author notes the comparisons use different measurement methods.

Converted model files, including Gemma-4-26B-A4B and Qwen3.6-35B-A3B, are published on Hugging Face. On Linux the user downloads a release tarball and runs ./janas-chat, which offers a model list. There are also an OpenAI-style server and an MCP tool. Windows 10 and 11 builds exist, and the README gives 34.2 tokens a second for Qwen3-30B-A3B on Windows 11.

The caveats are large. The README says the command line changes several times a week, stability is "not verified", and one GPU use caused a driver reset that took the desktop down. It reads the disk with O_DIRECT, which can push a machine into swap. All numbers are the author's, from one laptop, and nobody else has reproduced them yet.

Read it on the site: https://theaipost.net/story/find-janas-llm-ssd-experts/

## TerminalHorizon fine-tune lifts a 27B model to 55.8 on Terminal-Bench 2.0

**The TerminalHorizon paper reports a Qwen3.5-27B fine-tune that gains 14.2 points on Terminal-Bench 2.0 from synthetic long-horizon tasks, beating a rival 27B trained on roughly ten times the data.**

Researchers from the University of Science and Technology of China, Alibaba's AMAP unit and Southern University of Science and Technology published TerminalHorizon, a pipeline that synthesises long tasks for terminal-based coding agents. They say a Qwen3.5-27B model fine-tuned on its data scores 55.8 on Terminal-Bench 2.0, up 14.2 points from the base model's 41.6. The paper ranked among Hugging Face's daily papers with 28 upvotes.

The method has two stages, the paper says. First, tasks are built from real professional work, and an independent agent attempts each one and its trajectories then show where the task construction already did the key work, so the environment is rebuilt to require it. Second, accepted tasks are extended under the same goal with requirements that depend on earlier results.

The resulting dataset, TerminalHorizon-3K, holds 1,535 task environments and 2,852 trajectories covering 25 professional domains, with DeepSeek-V4-Pro as the teacher model. Trajectories average 52.8 turns. The authors fine-tuned for three epochs with supervised learning only and call the result TerminalHorizon-27B.

On other tests the authors report 55.0 on Terminal-Bench 1.0, 60.67 on Terminal-Bench 2.1, and 93.3 on AIME 2025, up 6.6 points. They say the 55.8 beats Terminal-Universe-27B, which scored 52.8, while using about a tenth as many trajectories. The paper also describes 12-hour research tasks where the model kept running experiments.

All figures are the authors' own and have not been independently reproduced. The paper links a Hugging Face collection for data and models, but the text we read does not say whether the synthesis code is released. The paper's results use a particular harness, Terminus2, so scores under other agent setups may differ.

## Nikkei says NTT is near a deal for Anthropic's first Japan data centre

**Nikkei Asia reports, citing unnamed sources, that NTT Data could spend $6.3 billion on an Osaka facility for Anthropic, with a partial opening expected by 2028.**

NTT Data Group is in the final stages of talks to build a data centre in western Japan for Anthropic, Nikkei Asia reported on Tuesday, citing multiple unnamed sources. It would be Anthropic's first dedicated facility in Japan. Nikkei says it would have one of the largest processing capacities in the country.

The paper says the Osaka site could cost $6.3 billion to build and could partly open by 2028. Techmeme's summary of the report puts the capacity at up to 500 megawatts. We could only read the opening section of the Nikkei article, so the rest of the deal's terms are not covered here.

No one is quoted by name. Neither NTT Data nor Anthropic has confirmed the talks in anything we have seen, and no other outlet has independently reported them, so the deal could still change or fall through. The numbers are Nikkei's, from its sources, not figures either company has published.

Nikkei's page also links a separate piece headlined "Anthropic eyes Japan expansion for Mythos AI, opposed by White House". We have not read it and cannot say how it relates to the Osaka plan or the talks.

Read it on the site: https://theaipost.net/story/find-nikkei-ntt-anthropic-osaka/

## AWS puts OpenAI's GPT-6 Sol, Luna and Astra on Bedrock for five Asian regions

**AWS says developers in Singapore, Jakarta, Thailand, Malaysia and Taipei can call GPT-6 models through Bedrock, where each output token uses up 10 tokens of quota.**

Amazon Web Services published a guide on Monday saying OpenAI's GPT-6 Sol and Luna can be reached through Bedrock global cross-Region inference from five source regions: Singapore, Jakarta, Malaysia, Thailand and Taipei. GPT-6 Astra is available only from Singapore. AWS says all three accept text and image input, tool use and prompt caching.

AWS describes Sol as suited to complex weekly tasks, Luna to high-volume repeatable work and Astra to complex reasoning and long documents. Sol and Luna accept reasoning effort from none to max, while Astra accepts the same levels except none. Four of the five regions are opt-in and must be activated first.

Access runs through the Converse API, or OpenAI's Responses and Chat Completions APIs on Bedrock. AWS says the ChatGPT desktop app and the Codex command-line tool can be pointed at it through a shared config file, with Codex CLI 0.148 or later. The post gives no per-token prices and refers readers to Bedrock's pricing page.

The quota rule is the detail to watch. AWS says input tokens count one to one against a tokens-per-minute quota but each output token consumes 10, and the maximum output length is reserved up front, so it should be set close to the expected reply. It recommends alarming at 70 to 80 percent of quota.

On data handling, AWS says metrics and billing stay in the source region, but traffic flagged by a classifier may be kept for up to 30 days in the destination region, and eligible customers can ask for zero retention. These are AWS's descriptions of its own service. OpenAI has not commented in the sources we read.

Read it on the site: https://theaipost.net/story/find-aws-bedrock-gpt6-asia/
